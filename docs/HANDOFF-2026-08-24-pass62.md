### 1.3 `lib/attribution` — why `unexplained` is not a plug

It would be trivial to make the bridge always close: compute every band, set the
last to whatever is left. That number would be meaningless, and the one output the
pass exists to produce would be the one nobody could trust. So `unexplained` is
**subtraction and nothing else**, and the *explanations* for it are a separate
input that is CHECKED against it:

- `attributedCents` — Σ restatements.
- `unattributedCents` — `unexplained − attributed`, **never clamped**. Positive is
  a hole nobody has accounted for; **negative means two explanations for the same
  money**, which is a defect in the attribution rather than in the ledger.

### 1.4 `services/attribution` — three choices, each found by measuring

1. **Half-open `(from, to]`.** Replay and `ledger-check` treat `from` as a
   baseline; `periodTotals` and `activeTxnsInRange` count it. The 2026-07-01
   boundary day alone carries **$1,454.90** — a bridge mixing the two misstates
   July by that much while reporting `unexplained = $0.00`.
2. **`REPLAY_STATUSES`, not `status='active'`.** An `excluded` row is hidden from
   analytics and still moves money — pass 59 found a fabricated plug behind
   exactly that.
3. **`moved` is a catch-all, never a `continue`.** `periodTotals` drops what it
   cannot classify — correct for a spending tab, fatal here, where a dropped row
   becomes phantom `unexplained`.

## 2. ⛔ NEXT — pass 62b, the renderer

Everything below is decided or measured. Nothing is left to default.

- **Copy `SankeyChart`, not `AllocationDonut`.** The plan's cited precedent is
  wrong: `AllocationDonut` is **recharts**. From SankeyChart take the
  `<title>`-not-`role="img"` a11y model (role="img" prunes the nested drill `<a>`
  from the a11y tree), the modified-click passthrough, and `useId()` for element
  ids — **ChartFocus renders its panel TWICE and keeps both mounted**, so any
  hard-coded id or `<defs>` id collides.
- ⛔ **Hue can never be the only carrier of direction.** Measured, and now pinned
  by a test as a LIMIT: `--positive` vs `--negative` is contrast **1.00** in light
  theme, 1.35 in dark. Use PnlCalendar's pattern — an aria-hidden ▲/▼ with neutral
  numerals. `--gain`/`--loss` exist, are Tailwind-mapped, and have **zero
  consumers**, so they can be given a meaning without touching any existing chart.
- **Split `moved` into named bands, starting with family pass-through.** The
  plan's own spec lists it, and it is currently inside `moved`. Measured:
  `Transfers > Family pass-through` is **+$43,863.44 across 28 rows**, all in Chase
  Checking, **all unpaired** — and `docs/adversarial-review-2026-07-27.md` finding
  81 records that **every one of the top eight single-day net-worth moves in the
  whole series is a Family pass-through row**. Naming it is most of this band's
  value. Also worth naming: `Gifts received` +$46,928.00 and `Internal Transfer`
  +$31,456.15 across 984 rows (which *should* net to zero and does not).
- **Seed the fixture BEFORE the baselines.** The e2e taxonomy has no
  `Family pass-through` (`src/db/seed.ts`), and `unexplained` has no seeded
  non-zero case, so both bands would photograph as structurally $0 in every
  baseline — pass 53's blindness, exactly.
- **Where it lives.** `PeriodSelector` already takes a `basePath`;
  `resolvePeriod` + `stepPeriodParams(period, -1)` give a window and its
  predecessor — the "moved from X to Y" framing, ready. A **new route** costs 8
  visual baselines + 2 axe tests + 3 overflow tests (`overflow.spec.ts` enumerates
  `src/app/**/page.tsx` off the filesystem and FAILS unless the route is listed).
  A **dashboard chart option** auto-generates its own tests from
  `DASHBOARD_VIEW_SPEC` — cheaper, and `ViewSwitcher` is already at its wrapping
  limit at 7 options, so an 8th costs a wrapped line at 320–440, not an overflow.
- **`ChartFocus` is coupled to `ChartRange` pills** (`activeRange: ChartRange`).
  A bridge scoped to a calendar month either accepts trailing-day framing or
  `ChartFocus` is generalised — which touches all four existing callers.
