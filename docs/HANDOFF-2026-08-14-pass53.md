## 2. 🔴 THE LESSON: a fixture that draws with a ruler makes every baseline blind

`e2e/seed-helpers.ts` stored its price **trend** as the series:

```ts
close = s.startPrice + (s.peakPrice - s.startPrice) * (i / riseDays);
```

Measured consequences: AAPL rose exactly **$0.1543/day for two years**, ETH fell
exactly **$23.33/day**, and summed against their quantities the portfolio moved
**−$168.7/day with ZERO direction changes** across the entire 30-day sparkline.
The AAPL holding page was a ruled diagonal from corner to corner.

The ugliness is the small half. The real cost:

> **A sparkline that renders as a straight segment is indistinguishable from a
> renderer bug that collapsed the series to its endpoints.** Forty-odd investment
> baselines could not tell those two apart, so they were blind to the exact
> failure mode they exist to catch.

🔴 **"Deterministic" had been quietly confused with "straight".** The docstring
promised *"fixed prices (no randomness)"* and *"every run — and every baseline
over it — is identical"*. Only the second clause was ever a requirement, and a
seeded PRNG satisfies it completely. The straightness was collateral that nobody
had priced.

### 2.1 The fix, and what it deliberately does not move

`priceWobble(symbol, t)` is now exported from `src/lib/fake-prices.ts` — lifted
out of `fakeDailyClose`, which already had exactly this noise+wave term, so the
fixture and the fake provider now wear one texture instead of two. Each seeded
close is `trend × priceWobble(symbol, i)`.

Two guards ran **before** anything downstream moved:

- the extraction is **output-identical**: 8,764 values across `fakeDailyClose`
  and `fakeIntradayClose`, 0 mismatches, checked against `git show HEAD:` — this
  matters because `src/services/prices.test.ts:70-88` pins per-symbol
  plausibility bands to those exact levels and that amplitude;
- the **last-day delta is pinned AFTER the wobble**, so each holding's day change
  in cents is byte-identical (AAPL +340c, MSFT −520c, WMT 0c, ETH 0c). That is
  what keeps the movers direction, the top-mover identity and the teaser's
  headline `−$132.00` exactly where they were.

Measured after: **65–68% direction changes per symbol**, from 0. Portfolio value
moved $55,681.64 → **$54,630.28**, which is fixture data and means nothing about
the owner's money.

### 2.2 ⚠️ The only thing holding this line is a script

`scripts/assert-fixture-shape.ts` (`pnpm assert-fixture-shape`, ~2s) reseeds a
throwaway database with the **real seeder** and asserts the series bends and the
last-day deltas are exact.

It is a script and not a vitest test because `e2e/**` is outside vitest's include
globs and the seeder wants a database on disk. **No unit test can import the
seeder.** Without this, deleting `close *= priceWobble(s.symbol, i)` is a
completely silent change — the only symptom would be baselines regenerated
straight again by whoever did it.

## 3. The second cause: the pace line was never straight

It was a **staircase drawn below its own stroke width**, which is a different
bug that looks the same from a metre away.

`projectedCents` is `actualToDate × daysInMonth / elapsed`, so the projection is
always ≥ every actual and **always owns the top of the y scale**. That is
arithmetic, not data, and it has a consequence worth stating as a law:

> the measured line's ceiling is pinned to exactly `elapsed / daysInMonth` of the
> band, on every day of every month.

On the 3rd it is stuck in the bottom tenth no matter what was spent. On the
fixture (8/31 elapsed) the whole 8-day range came to **2.0px against a 1.75px
stroke** — every feature sub-stroke, so 4 of 7 genuinely horizontal segments and
3 risers of 0.42/1.18/0.40px rendered as one flat hairline.

Now stepped and filled to a true zero. The step **asserts less** than the old
diagonal did: nothing was measured between two daily cumulative totals, so a
slope between them claims a trickle nobody observed. The fill restates the same
numbers as a region, which survives the squeeze the shared scale forces.

**The dotted projection was faded, not bent.** Owner picked "keep it but fade it
right back" from a concrete three-way choice. It is straight because it *is* a
straight-line extrapolation; curving it to look livelier would draw a shape
nobody measured. `--line-strong`, not `--ink-faint` — fainter in both themes
(light 0.82 vs 0.52; dark 0.40 vs 0.64 against a dark ground), and safe to fade
because the `<svg>` is `aria-hidden` with every figure printed as text beside it.

### 3.1 Why the geometry moved to `src/lib`

`src/lib/pace-geometry.ts`, under the 100%-branch gate, same doctrine as passes
50 and 52: **the e2e clock is pinned to `E2E_FAKE_TODAY`, so Playwright can only
ever render ONE day of ONE 31-day month.** Day 1, the last day (where the
projection becomes null) and a 28-day February are unreachable from every spec in
the suite.

That is precisely where the bug was. With nothing spent yet the old code drew **a
flat dashed rule across the full width, asserting a $0 month-end projection** —
measured on the real ledger at 2026-08-01: `projectedCents = 0`, solid
`"M 0.0 52.0"` (a lone moveto, which paints nothing), projection
`"M 0.0 52.0 L 240.0 52.0"`. The owner hits that on the 1st of every month.
`paceGeometry` now returns null there. 14 unit tests, none of which any e2e run
could have replaced.

⚠️ A `<circle>` was the wrong marker for "today": the viewBox uses
`preserveAspectRatio="none"`, which squeezes x to ~0.53 and would have hatched it
into an egg. It is a zero-length round-capped stroke, which `non-scaling-stroke`
keeps circular.

## 4. ⚠️ `--update-snapshots` would have left 6 baselines stale-but-green

Predicted blast radius was 52 PNGs. The first run failed **44**, and the gap is
the interesting part:

| page | changed | failed |
|---|---|---|
| dashboard, investments, investments-loss, holding, account-detail | 8 each | 8 each |
| **accounts** | **8** | **2** |
| **settings** | **8** | **2** |

`maxDiffPixelRatio` is **0.001**. A handful of changed digits on a 320×2600
full-page capture is ~0.096% of pixels — under the tolerance. Six `accounts`
baselines had genuinely moved (Robinhood is $54,630.28, verified by reading the
reseeded database directly) and passed anyway.

> **Regenerate by DELETING the PNGs.** Pass 51 learned that `--update-snapshots`
> will not refresh a diff inside the tolerance; this pass shows the same trap
> catching six files at once, silently.

Deleted 60, reran, confirmed **all 60 reported "A snapshot doesn't exist, writing
actual" and ZERO reported a pixel ratio** — i.e. nothing was quietly overwritten
on top of a real diff.

**`settings-*` renders net worth** (the Backups "Right now" panel), which
includes the portfolio. A dependency sweep explicitly listed it as safe. It was
not.

## 7. Notes for the next session

- **The fixture is a witness, not scenery.** If a fixture renders a shape that
  real data cannot produce, every baseline over it is weaker than its green tick
  suggests. Ask what a *broken* renderer would look like against this data.
- **Read the artifact, not a replica of the code that made it** (§5). A PNG in
  the repo is a source document.
- **Regenerate baselines by deleting them** (§4), and check the rerun says
  "snapshot doesn't exist" rather than reporting a pixel ratio.
- **Extract before you change.** Lifting `priceWobble` out and proving 8,764
  identical values first is what made the price change a one-variable
  experiment — `src/services/prices.test.ts` pins those levels and would have
  failed for a reason unrelated to the fixture.
- **Straight is sometimes correct.** The pace projection is a straight line
  because it is a straight-line extrapolation. Fading it was honest; bending it
  would have been fabrication.
- Still true: `rm -rf .next` if `next build` hits `ENOTEMPTY` after a Playwright
  run; `E2E_GATE=1` makes a missing baseline fail instead of being written; a
  peer session may be editing the tree (one was live this pass — re-check
  `git status` before committing).
